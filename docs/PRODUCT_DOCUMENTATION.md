# MIPS ERP & Portal — Complete Product Documentation

> **System Version:** 2.0 (High-Performance Free-Tier Edition)  
> **Target Institutions:** Malabar Institute of Paramedical Sciences (MIPS) & Allied Campuses  
> **Operating Environment:** Supabase Free Tier (PostgreSQL 15), Flutter Admin App (Desktop/Web), React Portal (PWA)

---

## 1. Executive Summary & Architecture Overview

**MIPS ERP** is an integrated institutional management system designed to manage the entire academic, administrative, and financial lifecycle of students and faculty. 

The system operates under a dual-frontend, unified-backend architecture:
1. **Flutter Admin App (`lib/`):** A responsive administrative dashboard deployed as a desktop application (Windows/macOS) and web portal for office administrators, principals, and accountants.
2. **React Student & Teacher Portal (`portal/`):** A lightweight, mobile-responsive Progressive Web App (PWA) designed for students and teaching faculty with offline support, low bandwidth consumption, and instant navigation.
3. **Supabase PostgreSQL Database (`supabase/`):** Central source of truth hosting relational entities, fine-grained Row-Level Security (RLS), and high-performance `SECURITY DEFINER` RPCs.

## 3. Authentication & First-Time Activation Architecture

To guarantee 100% uptime within Supabase free-tier quotas and prevent Edge Function cold-starts or HTTP 404 failures, all authentication is executed through native PostgreSQL `SECURITY DEFINER` functions with persistent credential storage.

### 3.1 Credential Persistence (`portal_credentials`)
Passwords created during first-time login or administrative resets are stored securely in `public.portal_credentials`:
```sql
CREATE TABLE public.portal_credentials (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    role text NOT NULL CHECK (role IN ('student', 'teacher', 'admin')),
    identifier text NOT NULL,
    password_hash text NOT NULL,
    is_temporary boolean NOT NULL DEFAULT false,
    updated_at timestamptz NOT NULL DEFAULT clock_timestamp(),
    CONSTRAINT uq_portal_credentials UNIQUE (role, identifier)
);
```

### 3.2 Student Authentication Flow
1. **Identifier:** Registration Number or Admission Number (e.g. `ADM-2026-0002` or `2024CS001`).
2. **First-Time Login:**
   - Student clicks **"First Time Login"** -> selects **Student** tab.
   - Enters Registration/Admission Number and Date of Birth (DOB).
   - Accepted DOB formats: `YYYY-MM-DD`, `DD/MM/YYYY`, `DD-MM-YYYY`, `YYYYMMDD`.
   - Client executes `portal_first_login_verify('student', identifier, dob, new_password)`.
   - Once validated against institutional records, the new password is saved to `portal_credentials`.
3. **Subsequent Logins:**
   - Enters Registration/Admission Number and the custom password.
   - Verified instantly via `portal_verify_login(identifier, password)`.

### 3.3 Teacher Authentication Flow
1. **Identifier:** Assigned username (e.g. `prof_kumar`, `ayesha_b`).
2. **First-Time Login:**
   - Teacher clicks **"First Time Login"** -> selects **Teacher** tab.
   - Enters Staff Username and registered 10-digit mobile number.
   - Client executes `portal_first_login_verify('teacher', username, phone, new_password)`.
   - Once validated against the mobile number saved during provisioning, the new custom password is saved to `portal_credentials`.
3. **Subsequent Logins:**
   - Enters Username and custom password (or temporary assigned password).
   - Validated through `portal_verify_login(identifier, password)`.

## 4. Administrative Features & Workflows

### 4.1 Teacher Provisioning & Management
Administrators manage staff members via the Flutter Admin App with zero Edge Function dependency:
* **Provisioning (`admin_upsert_teacher`):**
  - Name, Username, Phone number, and optional temporary password.
  - Automatically provisions the teacher record in `public.teachers` and establishes credentials in `public.portal_credentials`.
* **Listing (`admin_get_all_teachers`):**
  - Returns all teachers with their marked attendance session counts in a single network round-trip.
* **Status Control (`admin_set_teacher_active`):**
  - Instant activation or deactivation of teacher accounts. Deactivated staff are immediately blocked from logging in.

### 4.2 Student Lifecycle Management
* **Admissions & Enrollment:**
  - Automated or manual Admission Number and Registration Number allocation.
  - Course, Batch, and Semester assignment.
* **Status Transitions:**
  - States: `active`, `discontinued`, `tc_issued`, `completed`, `passed_out`.
  - Non-active statuses automatically lock portal access and exclude students from active attendance sheets.
* **Semester Promotion:**
  - Bulk promotion preview with eligibility checks (attendance percentage thresholds and fee clearances).

### 4.3 Academic Attendance Management
* **Session Creation:** Teachers or admins create a session for a specific Date, Period, Course, Batch, and Subject.
* **Batch Marking:** Attendance status (`present`, `absent`, `late`, `excused`) is recorded in bulk.
* **Shortage Alerts:** The system flags students whose aggregate attendance falls below 75%, generating automated shortage lists.

### 4.4 Fees & Accounts Ledger
* **Fee Structure Definition:** Tuition, lab, examination, and admission fees configured per course/semester.
* **Collection & Receipts:**
  - Payment recording (Cash, UPI, Bank Transfer).
  - Instant print-ready receipts with automated sequential numbering.
* **Ledger View:** Tracks balances, partial payments, and overdue amounts per student.

## 7. Cost & Performance Optimizations (Supabase Free Plan)

To operate within Supabase Free Tier constraints without service interruptions:

### 7.1 Single-RPC Screen Architecture
Replaced multi-request queries with single consolidated PostgreSQL RPCs:
* `get_admin_dashboard_summary()`: Combines counts, fee collections, attendance stats, and recent activities.
* `get_student_portal_overview()`: Combines student profile, current semester, attendance summary, and dues.
* `get_teacher_today_board()`: Combines today's schedule, pending attendance sessions, and quick stats.

### 7.2 Database Size & Storage Guards (500 MB Limit)
* **Automated Data Purge (`pg_cron`):**
  - Read notifications older than 90 days are purged daily.
  - Audit log entries older than 12 months are cleaned up automatically.
  - Stale push notification tokens are pruned.
* **System Health Monitor (`admin_get_system_health`):**
  - Real-time tracking of database size (MB), percentage of 500 MB quota used, row counts of the top 15 tables, and slow query previews.
  - Warning threshold triggered if database utilization reaches 70% (350 MB).

### 7.3 Bandwidth (Egress) Reduction
* **Select Exact Columns:** No `SELECT *` in production queries; all RPCs return trimmed JSON payloads.
* **Client-Side Caching (TanStack Query):**
  - Static reference data (courses, subjects): `staleTime: 12 hours`.
  - Academic summaries: `staleTime: 5 minutes`.
  - Notifications: `staleTime: 30 seconds`.
